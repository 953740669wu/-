# S04：跨层 bf16 与数值验证

先读同目录 `README.md`、`REPORT_TEMPLATE.md`、S00 和已接受的内存阶段报告，以及本聊天给定的集成清单。

## 目标

减少层与层之间搬运的数据，验证 bf16 对真实训练步骤是否有收益。已有“每次线性计算前后转换格式”的方案更慢，不能重复该方案后宣称新优化。

## 范围与前置

只写 `work/S04/`，在 `s4_models.py`、`kml_ops.py` 的独立候选副本中改精度路径；不改 HBM 分配器、注意力内核或模型结构。内存阶段评审后执行性能候选。先交出 dtype/张量布局/累积精度接口说明，S05 接据此开发。

## 工作

1. 先固定 fp32 和混合精度参考、随机输入、权重、容差与 loss 度量。对算子输出、输入/权重梯度和一次 AdamW 更新写检查。
2. 画清每个模块输入/输出 dtype 与转换位置，保留 fp32 主权重、优化器状态和必要的稳定计算。避免把已知很慢的 bf16 卷积反传直接开启为全局默认。
3. 对 KML bgemm 长 K 的累积误差、sbgemm 的 beta/初始 C 行为做实际检查；dW 要用已验证的 fp32 累积路径。不得把 bf16 GEMM 的峰值当作整步加速。
4. 从一个编码器 block 的最小候选开始，只有输出/梯度与耗时过关再扩至整编码器/解码器。给出转换次数、转换耗时和中间张量大小。
5. 固定随机序列进行至少 200 次更新，对照 fp32 loss 轨迹、梯度与权重漂移；loss 相对差异目标 ≤1%，分母与聚合方式事先说明。随后按四域/整节点验证总步吞吐与内存。

## 验收与交付

- 精度策略明确，数值检查通过，无 NaN/Inf、缺失梯度或偷偷改变损失/批量。
- 总步收益超过波动；原计划 C 阶段单域 50/5 帧每秒等目标可作为历史门槛单列检查，接受结论必须依靠 ≥4 域及整节点实测。
- `work/S04/REPORT.md`、dtype 接口、候选/diff、数值测试和 200 步数据、阶段及整步性能。通过工程数值检查仍不能声称正式训练质量已验证。
