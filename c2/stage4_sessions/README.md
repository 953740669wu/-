## 5. 统一验收方法

### 正确性

- 同一初始权重、同一输入和预先固定的随机变量，比较输出、loss、每个应有梯度及一次 optimizer 更新后的权重；检查缺失梯度、NaN/Inf、shape/dtype、参数与 state_dict 兼容性。
- fp32 等价改动参考现有约 `1e-6` 的梯度相对差异记录，明确每种误差的定义、参考量、接近零的处理及最大误差；它不是所有算子的统一硬阈值。根据 S00 实测和算子性质在实现前写明容差，不得看结果后放宽。
- bf16 是精度策略变化，不宣称逐位一致。注意力沿用原计划：fp32 输出及梯度相对误差不超过 `2e-6`，bf16 不超过 `2e-3`；先固定度量定义。bf16 整步需固定随机序列进行至少 200 次更新，报告 loss 轨迹；原计划的 loss 相对差异目标为 ≤1%，达标也不能替代最终训练质量验证。
- 内存优化不能靠少算样本、少做 optimizer step 或改变损失归一化获得速度。梯度累积需以相同有效批量比较；掩码样本数等分母要匹配整批计算。

### 性能与内存

- 顺序是单域正确性/小试 → 至少四域并发 → 整节点。单域×16 只可标为预测。
- 基线与候选使用同主机、同输入、同精度/有效批量/线程绑定、相同预热和计时长度；先验证至少四域，才扩大实验。按 A/B、必要时 A/B/A 排序减少环境漂移影响。
- 正式接受结果至少三个独立轮次，逐工作负载报告 `(max-min)/mean`，原计划稳定性目标 ≤5%。达不到时保留全部结果，标记不稳定，不取最好一轮。稳定性方案及最终集成方案还需第二台主机验证。
- 记录每域最慢值/中位数、全部域吞吐之和、`域数 × 最慢域吞吐`。后者只是同步训练前的保守参考，不含通信；实际同步训练吞吐必须由 S07 计时。
- 必须检查期望域数、结果文件数、进程退出状态、超时及配置一致性。缺域/失败/沿用旧结果时，该轮不能 PASS，不能只用成功域重新算一个“整节点”数字。
- RSS 在 hugetlb HBM 下不包含全部内存。分别记录 DDR、HBM 实际占用/高水位及测量方法；不能用累计分配字节冒充峰值驻留或访问带宽。
- 每项同时报告总步耗时、各阶段耗时、速度变化、误差、节点小时和未完成验收。微算子变快不等于训练步骤变快。
- 本轮新增的候选采用建议接受门槛：相同工作负载下中位总步耗时至少减少 10%，且收益超过测量波动；若收益较小但稳定性或内存改善有独立价值，可单列提交本聊天评估。10% 是本轮工程筛选建议，不是原文档已达成指标。
