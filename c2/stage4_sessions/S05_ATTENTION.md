# S05：注意力计算加速

先读同目录 `README.md`、`REPORT_TEMPLATE.md`、原计划 D、既有 attention 失败实验和最新接受版本。

## 目标

优先改善 32 电极长序列注意力的前向与反向计算，同时减少中间数据搬运。

## 前置与边界

只写 `work/S05/`。内存阶段评审后可做工具链探针；S04 dtype 接口及本聊天接受版本明确后实现候选。候选自包含，涉及 `kml_ops.py`/模型接入时只提交副本与最小 diff，不改正式共享入口、卷积、HBM 策略和其他 session 代码。

## 两道检查点

1. **先判可行性。** 核实计算节点实际 ISA、编译器、torch 扩展头文件、KML 调用约定和动态加载路径。编译并运行最小探针；能编译不等于能执行。没有工具链或出现 SIGILL 时提交证据与有限替代方案，先回本聊天评估，不无限安装/重写底层内核。
2. **再做最小候选。** 优先基于可用工具链做有界分块、在线 softmax 和前后向；如需直接 SME 指令且工具链未验证，不先铺开大实现。既有 `gemm_attention` 已被记录为慢 4–9 倍，只有明确减少中间内存/数据遍历才值得重试。

## 验证

- 先小尺寸验证，再覆盖编码器 `[64,8,208,64]`、`[64,8,928,64]` 和交叉注意力 Q 长 256、K/V 长 928 的实际布局；可先小 B 正确性，但目标 B/微批按接受配置实测。
- 与 SDPA 比较输出、dQ/dK/dV；fp32 相对误差 ≤2e-6，bf16 ≤2e-3，固定并说明误差定义。测试实际支持的掩码/缩放/布局；不支持的接口明确回退或报错，不能静默忽略。
- 不改变参数含义、state_dict 或注意力数学定义。必要时做小型高精度梯度检查，再进入真实规模。
- 同时测 fwd+bwd、峰值内存和整个训练步骤。单域正确后至少四域，再整节点；原计划 attention ≥4 TFLOP/s、4.6→≤1.2 秒只按一致 FLOP/shape/线程口径检查，不拿历史秒数替代本次对照。
