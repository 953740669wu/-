# 独立任务的固定交接约定

2026-11-05起执行，依据用户明确要求。保留现有会话和任务目录，不靠搬运完整聊天续接。

## 日常入口与归属

- 总协调只维护`work/COORDINATION/STATUS.md`总任务表和自己的状态/变化摘要；任务各自维护`work/<任务>/SESSION_STATUS.md`与`ROUND_DELTA.md`。Git窗口使用`work/GIT/`。未来任务启动时按模板创建自己的两个文件。
- `SESSION_STATUS.md`是当前快照，建议不超过40行：目标/进度、修改文件、测试/证据、阻塞、下一步、轮次/更新时间。详细文件列表和指标用清单/证据路径代替展开。
- `ROUND_DELTA.md`只保存最近一轮变化，建议不超过12行。旧轮详情保留在原报告、独立证据目录和Git历史，不在状态文件累积长日志。
- 本次总协调为已有任务初始化状态，注明是依据已审核成果整理；之后由对应任务会话更新。状态表不等于已启动、已提交作业或已验收。

## 每轮固定流程

1. 继续现有会话，先读自己的状态/最新变化及总任务表；只按当前目标打开必要参考。无需重读整段聊天、所有报告或其它任务的历史。
2. 分派必须给出三项：**本轮目标、参考文件、完成标准**。参考只列本轮必需文件/章节；改代码前核对相关源码、依赖和输入的最新版本/SHA及是否仍在写入。
3. 验收或排查问题时，总协调读取相关实际代码、差异和原始证据；简短状态不替代科学数值、资源或来源核验。未核验的作者状态不能自行变成总协调接受。
4. 每轮结束或需要中断时，更新自己的状态和变化摘要。详细REPORT只按验收需要生成/更新；对总协调只汇报下面六行，不重复整份历史。

```text
任务/轮次：
状态变化：
本轮改动：
验证增量：
证据：SESSION_STATUS.md / ROUND_DELTA.md / 本轮报告或清单路径
阻塞与下一步：
```

测试增量写本轮实际运行的检查、数量与结果；未运行就明确写未运行，不把旧结果冒充新验证。没有新代码/测试也如实说明。

## 会话过长的续接

原会话先更新上述两个文件，写明未完成操作、活动进程/job ID或“尚未核实”、当前目录/版本及下一条动作。只有状态已保存后才换会话。新会话先读两个文件、总表和必要证据，核对实际文件/进程后续做；不复制完整聊天。原会话无法恢复时由总协调从磁盘整理，明确哪些状态无法确认。

## 保持的边界

继续遵守独立候选目录、实际36核约定、原数值阈值和有界作业安排。资源越界/运行前提错误与数值FAIL分开；候选准备、集群通过、生产接受分别记录。

任务会话不切换共享目录分支或操作共用暂存区。总协调核验后主动提醒提交；由Git窗口精确选择已审核文件，区分本地commit与远端push，回传结果。新增状态约定不触发任何集群作业或自动提交。
